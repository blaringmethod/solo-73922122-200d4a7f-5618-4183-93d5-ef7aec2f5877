# 晶圆缺陷坐标复查

用第一道工序（基准图）的晶粒网格，为同一片晶圆上各道工序留下的缺陷换算统一坐标。
网页上传最多 6 道工序的 CSV，SQLite 保存原始记录；定位点更正/撤去后，所有受影响
工序的查询结果一并重算；无解或保存失败时整套改动回滚。

另支持**两片同规格晶圆的同名非基准工序明细对调**：同一道工序的 CSV 在两片之间传反
时，可先只读试算两片换前/换后的待定缺陷数，确认后在一个事务里整份互换定位点与缺陷。

## 快速启动

```bash
docker compose up --build -d
# 打开 http://127.0.0.1:8000
```

首次打开可点“新建复查 → 一键填入演示数据”，或从“新建复查”页下载 `samples/`
里同名的 6 个 CSV 再上传。数据保存在 Docker 卷 `wafer-data` 里，删除容器不会丢。

本机不装 Docker 时：

```bash
python3 -m pip install -r requirements.txt
WAFER_DB=data/wafer_review.sqlite3 gunicorn --bind 0.0.0.0:8000 wsgi:app
```

## CSV 格式

每行一个定位点或缺陷，字段为“类型, 编号, 行, 列”，行列从 1 起算：

```csv
类型,编号,行,列
定位点,L1,2,7
定位点,L2,2,6
缺陷,D101,4,4
```

* 类型可写“定位点 / 缺陷”，也接受 `locator / defect`、`L / D`；
* 表头可有可无，中英文表头均可，列顺序按表头识别；
* 同一个**定位点编号**在不同工序里代表同一枚物理标记，这就是对齐的依据；
* 基准图没有的定位点编号，只要在多道工序之间同号，也参与约束（见下文）。

示例数据在 `samples/`，可用 `python scripts/gen_samples.py` 重新生成。

## 对齐模型

每道工序可独立选择以下 8 种变换之一（基准图固定为“原样”）：

| 变换 | 说明 |
| --- | --- |
| 原样 / 顺时针90° / 旋转180° / 顺时针270° | 纯旋转 |
| 左右镜像 / 镜像+顺时针90° / 镜像+旋转180° / 镜像+顺时针270° | 镜像或镜像叠加旋转 |

一个**方案**是“每道工序各选一个变换”。约束是：所有同号定位点换算到基准坐标系后
落在同一格；若基准图里也有该编号，这个格子还必须正是基准图上的位置。

* 不同工序可能通过“基准图没有的同号定位点”互相牵制，所以枚举的是**全局方案**
  （最多 8⁵ = 32768 种组合，实测约 0.2 秒）；
* 查询“工序 + 缺陷号”时，收集该缺陷在**所有可行方案**下的落点：
  * 都落在同一格 → 给出基准坐标；
  * 落在不同格 → 标为**待定**，并列出候选格；
  * 不存在任何可行方案 → 无解（正常保存流程不会留下这种状态）。

查询结果不落库，每次由已保存的定位点即时推导，因此定位点与结果天然同步。

## 更正与撤点

* 每个定位点都可改行列，或整体撤去；
* 撤点/更正和随后的可行性校验在**同一个 SQLite 事务**里完成：校验不通过就整体
  回滚，原定位点、原查询结果保持不变，页面给出“未生效”提示；
* 改动成功后，所有工序的查询结果立即按新定位点重新推导，不需要重新上传。

## 两片晶圆对调工序明细

适用场景：两片**同规格**晶圆（网格尺寸、工序数、各工序序号与名称完全一致）的同一道
非基准工序 CSV 在上传时传反了。入口在首页“两片晶圆对调工序”，或晶圆详情页
“与另一片对调工序”；首页的“一键建立对调演示（两片）”会造好一对传反的晶圆并跳到
试算页（传反的是第 6 道“封装”工序）。

操作分两步：

1. **试算（只读，不落库）**：从同一已提交状态取两片的数据，在内存副本上整份互换该
   工序的定位点与缺陷，显示两片各自**换前 / 换后的待定缺陷数**（含逐工序明细）、可行
   方案数变化，以及换入明细与该片其他工序共享的同号定位点。试算期间补点、改点、撤点
   照常进行，互不阻塞。
2. **确认（一个事务写两片）**：表单带着试算时两片的修订号提交。取数后任一片被成功
   改动过定位点或对调过明细（修订号已变），确认会被拒绝并提示**重新试算**；通过后
   两片的工序明细、修订号和坐标查询在同一事务里一并更新，任一片校验或保存失败则两片
   一起回滚到对调前。

规则与语义：

* 基准工序（第一道）不参与对调；只能选择两片上同名、同序号的非基准工序；
* 对调是**整份明细互换**：定位点与缺陷的编号、行列全部随明细走，因此两份明细可以
  带相同编号（同号可不同位），数据库记录重新插入、不复用旧主键；
* 换入明细必须与该片**另一道工序存在同号定位点**，且对调后两片各自仍有可行方案，
  否则试算即报错，不会进入确认；
* 对调成功后两片修订号各 +1，查询结果仍由已保存定位点即时推导，天然同步。

## 演示脚本

`samples/6_封装.csv` 只有 C1 一个定位点，而基准图没有 C1——它靠与“沉积”共享
C1 才能对齐。因此：

| 操作 | 结果 |
| --- | --- |
| 初始状态 | 可行方案 2 套；封装 D101/D103/D105 有坐标，D102/D104 待定 |
| 撤去“沉积”的 C1 | 可行方案变 8 套，封装全部缺陷变待定（演示“撤点影响其他工序”） |
| 补回后把封装 C1 更正到 (4,4) | D104 由待定变确定 (5,5)（演示“更正后结果更新”） |
| 把封装 C1 改成 (1,1) | 无可行方案，操作被拒绝，定位点与结果保持原样 |

网页上的“全部工序叠加到基准坐标系”图，用每道工序的第一个可行变换把定位点和缺陷
画到同一张网格上，便于肉眼核对。

### 对调演示（两片晶圆）

首页“一键建立对调演示（两片）”建立甲、乙两片同规格晶圆，二者“封装”CSV 互相传反：
甲片当前持有的封装明细多一枚基准同号定位点 L1（唯一变换，0 个待定），乙片持有的
标准封装只有 C1（2 套方案，D102/D104 待定）。试算与确认时可看到：

| 时点 | 甲片待定缺陷 | 乙片待定缺陷 |
| --- | --- | --- |
| 换前（传反状态） | 0 | 2 |
| 换后（各归各位） | 2 | 0 |

两片的 D105 同号但行列不同，对调后随明细一起搬家，可在详情页坐标查询里核对。

## 架构

```
wafer_review/
├── app.py         Flask 应用工厂与路由
├── geometry.py    8 种 D4 变换与逆变换
├── csvparse.py    CSV 解析与校验
├── db.py          SQLite schema（wafer / step / locator / defect）
├── model.py       方案枚举、可行性、逐缺陷查询
├── service.py     上传、更正、撤去、两片对调（事务 + 回滚）
├── swap.py        对调领域逻辑：同规格校验、内存试算、修订号核对
├── overlay.py     多工序叠加视图
├── gridview.py    网格渲染数据
├── demo.py        演示数据（单晶圆 6 工序 + 两片传反对）
└── templates/ static/
```

## 自测

```bash
python3 -m pytest tests -q          # 112 项单元/集成测试
python3 scripts/selftest.py         # 脚本化走查关键操作（临时库，40 项检查）
BASE_URL=http://127.0.0.1:8000 python scripts/selftest.py   # 打真实服务
```

## 限制

* 每边格数可设为 2–60（默认 8），但变换只覆盖**正方形**网格的对称操作；非正方形
  的晶粒排布不支持；
* 不解析缺陷明细图/坐标文件，只认 CSV；
* 认证与多用户隔离未实现，定位点操作对所有访问者开放——仅适合内网质检工具场景。
